# config/reference/

Reviewed reference CSVs that silver needs: label → PSGC code maps, cause maps, the disease directory, area exceptions and row overrides. They are **inputs**, not data. Each domain's `*_silver_00_reference.sql` loads them into silver tables, and the silver builds join to those tables.

## Where each copy lives

| Copy | Path | Role |
|---|---|---|
| Repo | `config/reference/<domain>/` | Reviewed record, changed by PR |
| Volume | `<landing_root>/reference/<domain>/` | What `*_silver_00_reference.sql` reads |

`<landing_root>` = `/Volumes/workspace/default/ftw-b12-de/groups/g5_landing`

The two copies must be identical. After a PR is merged, upload the changed files to the Volume and rerun the domain's `00_reference` step.

## Rules

1. **Generated files are never edited by hand.** Change the builder's decision table, rerun the builder (see `builders/README.md`), review the diff and commit. Hand edits are lost on the next run.
2. **No hand-edited files since 2026-10-14.** Every decision lives in a builder's decision table with who decided it and when.
3. **Every column is text.** PSGC codes keep their leading zeros (`0102800000`). Do not open and save these files in Excel: it drops the zeros and changes dates.
4. **Column order matters.** `read_files` reads by position with a fixed schema. Adding, removing or reordering a column means changing the schema string in `00_reference.sql` in the same PR.
5. **Codes come from geography silver only.** Every PSGC code here must exist in `public_health.silver.geography_silver` at the stated level. The builders check this before writing, and `00_reference.sql` checks it again. After a new PSGC snapshot, rerun the builders.
6. **Stale files stop the run.** `facilities_area_exceptions.csv` carries the `geography_checksum` it was built from. Workforce overrides carry the workbook `_content_checksum` they were reviewed against. If either no longer matches, the load fails until the file is regenerated and reviewed.
7. **Unresolved means quarantined.** A label with no usable row is never matched by name. Its records are held back (facilities rows that aren't usable load as `match_type = 'unresolvable'`).

## Changing a reference file

1. Change the builder's decision table (`DECISIONS`, `ID_MAP_OVERRIDES`, `HDX_MANUAL`, `OVERRIDES`, ...) with `reviewed_by` / `reviewed_on` where the table has them, rerun the builder, read its report.
2. Review the diff and commit it in the same PR as the change that caused it (new source, new PSGC snapshot, decision).
3. After merge, upload the file to `<landing_root>/reference/<domain>/`.
4. Rerun `<domain>_silver_00_reference.sql`. All checks must return 0. Then rerun the silver builds that read it.

## Adding a reference file

1. Put it in its domain folder; name it `<domain>_<content>.csv`.
2. Add a load block and checks (duplicate key, codes in geography, not empty) to the domain's `00_reference.sql`.
3. Add a row to the table above, marked G or H.
